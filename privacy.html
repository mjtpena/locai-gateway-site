Privacy policy

Locai Gateway runs on your PC and keeps what it records there. This page says exactly what that is.

The short version

  • Locai Gateway has no servers. Nothing it records is sent to us or to anyone else.
  • It makes no internet connections. It accepts connections from your own PC and forwards requests only to AI runtimes on the same PC.
  • It has no telemetry, no analytics, no advertising and no crash uploads. There is no account.
  • It keeps an activity log on your PC so that you can see which apps used your local AI. Prompt and response text is not stored unless you turn that on.
  • Activity records are deleted after 30 days unless you choose another period. Uninstalling the app removes its data.

Who and what this covers

Locai Gateway is published by mjtpena ("we"). This policy covers the Personal edition of Locai Gateway, distributed through the Microsoft Store, and this website.

The app is a gateway that runs on your Windows PC between your apps and your local AI runtimes (for example Ollama, LM Studio, Jan, GPT4All, llama.cpp and Foundry Local). Everything described below happens on your PC, under your Windows account.

What is stored on your PC

The app keeps its data in one folder, %LOCALAPPDATA%\Locai\Gateway. When the app is installed from the Microsoft Store, Windows keeps that folder inside the app's own package storage. The folder holds a database (gateway.db), your settings and rules (policy.json), diagnostic logs, and a few small state files such as a marker that first-run setup is finished.

A record of each request

For every request an app sends through the gateway, the activity log stores:

KindWhat is stored
When and whoThe time, a request ID, the app that sent it, its process ID, and the Windows user identifier (SID) and session number of the account it ran under.
What was asked forThe HTTP method and path (for example POST /v1/chat/completions), the type of endpoint, the model name that was requested, the runtime and model that served it, and whether the reply was streamed.
What happenedWhether the request was allowed, denied or failed, the error code and HTTP status, the rule that applied, and the first 8 characters of the per-app API key if one was used.
Size and timingPrompt and completion token counts (and whether they were estimated), how long the request took, the time to the first byte of the reply, the time spent inside the gateway, and how many fallbacks were tried.
RedactionHow many matches each detector found. Counts only: the matched text is not stored.

The text of prompts and responses is not part of this record. See Prompt and response text.

A list of apps

For each app that has sent a request, the app list stores: its display name; whether it is an app, a browser, a script interpreter or a relay; the path and file name of its executable; its package family name; the publisher named in its code signature; its signature status; a SHA-256 hash of the executable; the Windows user identifier it ran under; when it was first and last seen; and a small icon when one is saved. For a request from a web page, the website's origin (for example https://example.com) is stored. For a script interpreter such as python.exe or node.exe, the path of the script is stored.

Events

The app records events such as: a consent prompt was shown and how you answered; settings or rules changed; a runtime was found or its health changed; the gateway was paused or resumed; an API key was created or revoked; port takeover was turned on or off. An event holds a few details, such as the app, the model name, a local address or a port number.

Usage totals

For each app, the number of requests and tokens per day and per month, used to enforce the limits you set.

Your settings and rules

Your rules for each app (which can name a package, a publisher, an executable name, path or hash, a website origin, and for a script the script path or command line), limits, redaction settings including your own patterns, the list of runtimes, and preferences such as theme and notifications.

Keys

If you create a per-app API key, the app shows it to you once. It stores only a SHA-256 hash of the key, its first 8 characters and your label. If you give the gateway an API key for one of your runtimes, it is stored encrypted (see How secrets are protected).

Prompt and response text

To do its job the gateway reads each request in memory as it passes through: it looks for the model name, applies redaction and forwards the request. What it keeps afterwards depends on the What gets recorded setting on the Privacy tab:

  • Details only (the default). No prompt or response text is stored.
  • Details and a fingerprint. Only a SHA-256 hash of the prompt text, taken after redaction, is stored. The response is not stored. The hash has no salt, so the same prompt always gives the same hash: someone who has your database and can guess a prompt could confirm the guess.
  • Everything. The prompt text, after redaction, and the response are stored, each cut off at 256 KB. Both are encrypted with Windows data protection (DPAPI) for your Windows account before they are written.

Text is stored only for requests that were allowed. If a request is blocked, its text is not stored in any mode.

Diagnostic logs and bundles

The background host and the tray app each write a small diagnostic log in the logs folder, one file per day, keeping the newest seven. The logs record start-up, the ports in use, the local addresses requests were forwarded to, and what failed and where (the error type and message, and for the tray app a stack trace). The app does not write prompt or response text, API keys or secrets to these logs.

If you create a diagnostics bundle in Settings, the app writes a zip file to your temporary folder and shows you where it is. The bundle contains the gateway's current status (ports, runtimes and their local addresses, model names, today's totals), your effective settings and rules, the app version and Windows version, and up to seven recent log files. It does not contain prompt or response text, API keys or stored secrets. The bundle is not sent anywhere. Your rules can include file paths, which may contain your Windows user name, so read the bundle before you share it.

If you export the activity log to a file, the file is saved where you choose and is yours to manage.

What the app looks at

To tell apps apart, the gateway asks Windows which process opened each connection and reads that program's executable path, version information, package identity, code signature, user identifier and parent process. For script interpreters and relays (for example python.exe, node.exe, PowerShell, curl.exe or the WSL relay) it also reads the command line, to find the script being run.

To find your runtimes, it sends small requests to the usual runtime ports on 127.0.0.1, checks which process is listening, and, if the Foundry Local command-line tool is installed, asks it for its address. It also checks the list of connections between programs on your PC so that it can tell you when an app talks to a runtime directly instead of through the gateway.

If your PC is managed by an organisation, the app reads that organisation's policy settings for Locai Gateway from the Windows registry.

Changes it makes to your PC

  • Start at sign-in. Locai Gateway is registered to start when you sign in: its tray icon appears, with no window, and starts the background host. You can turn this off in the app's Settings, or in Windows Settings under Apps, then Startup.
  • Notifications. Consent prompts are shown as Windows notifications. A prompt shows the app's name, its publisher or file path, and the model it asked for.
  • Port takeover (off by default). If you turn it on, the app sets the OLLAMA_HOST environment variable for your Windows account to 127.0.0.1:11435, restarts Ollama and listens on port 11434 itself. It saves the previous value and puts it back when you turn port takeover off or quit Locai Gateway. It also puts it back when the gateway shuts down normally, for example at sign-out, unless you chose in Settings to keep runtimes blocked while the gateway is stopped. If the app is removed or stops unexpectedly while port takeover is on, the variable can be left behind. The support page explains how to reset it by hand.

What is never collected

  • We receive no data from the app: no usage statistics, no analytics, no crash reports, no prompts, no model names, no list of your apps.
  • There is no account, so there is no name, email address or password to give.
  • There is no advertising and no tracking.
  • The app does not check for updates itself. Updates come through the Microsoft Store.
  • We do not sell or share your data. We do not have it.

Network connections

The gateway listens only on the loopback addresses 127.0.0.1 and [::1], which other computers cannot reach. It refuses to start a listener on any other address.

The only connections it opens are to your runtimes, and it checks each one: a runtime address must be an http:// address on 127.0.0.1, [::1] or localhost, and at connection time every address the name resolves to must be a loopback address or the connection is refused. System proxy settings are not used.

The tray app and the background host talk to each other over a named pipe on your PC.

Retention and deletion

  • Requests and events are deleted when they are older than the retention period. The default is 30 days. You can set it from 1 to 3,650 days on the Privacy tab. Clean-up runs when the gateway starts and once a day.
  • Stored prompt and response text is deleted together with its request.
  • Apps that have not been seen within the retention period are removed from the app list.
  • Usage totals are kept for up to about three months, then deleted.
  • Diagnostic logs are kept for seven daily files each.
  • Rules, settings, API key records and runtime keys stay until you delete them in the app or uninstall it.

To remove old activity sooner, lower the retention period; records older than the new period are deleted at the next clean-up. To remove everything, uninstall Locai Gateway: Windows deletes the app's data folder with it.

Two things are outside that folder and are not removed by uninstalling: a diagnostics bundle or an exported file that you created, and the OLLAMA_HOST variable if port takeover was still on (see how to reset it).

If the database file is ever found to be damaged at start-up, the app renames it and starts a new one. The renamed file stays in the data folder until you delete it or uninstall the app.

How secrets are protected

  • API keys that you store for your runtimes, and prompt and response text when you have chosen to record everything, are encrypted with Windows data protection (DPAPI), using a key that Windows ties to your Windows account.
  • Per-app API keys are stored only as SHA-256 hashes.
  • The rest of the database (the activity log, the app list and usage totals) is not encrypted. It sits in your user profile and is protected by the file permissions of your Windows account.

Microsoft, your runtimes and this site

  • Microsoft Store and Windows. Microsoft delivers the app and its updates, and Windows may send its own diagnostic data, including crash data, to Microsoft according to your Windows settings. Microsoft may show publishers summary statistics from that data. This is governed by Microsoft's privacy statement, not by this policy, and the app itself sends nothing.
  • Your runtimes and apps. Ollama, LM Studio and the other runtimes, and the apps that use them, are separate products with their own privacy practices. If a runtime sends data elsewhere, for example to download a model or to use a model hosted by its maker, that is between you and that runtime.
  • This website. The site is a set of static pages hosted on GitHub Pages. It sets no cookies and runs no analytics or scripts. GitHub, as the host, may log technical details of visits such as IP addresses, as described in GitHub's privacy statement.
  • Support. Support is handled in a public issue tracker on GitHub. Anything you post there is public and is handled by GitHub under its privacy statement. Please do not post prompts, keys or other private data.

Children

Locai Gateway is a utility for people who run AI models on their own PC. It is not directed at children. It does not collect personal information from anyone, including children, because nothing it records leaves the PC.

Changes to this policy

If the app changes in a way that affects this policy, we will update this page and the date at the top, and describe the change in the release notes of the version that introduces it.

Contact
