Get help

Support is handled in a public issue tracker:

Open the issue tracker

Search first, since someone may have asked already. For a new issue, these details save a round trip:

  • What you did, what you expected and what happened instead.
  • The Locai Gateway version (Settings, under About) and your Windows version.
  • The runtime you use, such as Ollama or LM Studio, and its version.
  • The error code the app received, if there was one. See Error codes.

The tracker is public. Do not post prompts, API keys or other private data. If you attach a diagnostics bundle (you can create one in Settings), read it first: it holds your rules and log files, which can include file paths with your Windows user name. It does not hold prompt text or keys.

Connect an app

Change the address the app uses for its AI server. With the default port:

The app speaksUse this address
OpenAI APIhttp://127.0.0.1:11500/v1
Ollama APIhttp://127.0.0.1:11500

If an app insists on an API key, any value works unless you have set the app's rule to require a Locai Gateway key. In Python with the OpenAI library:

from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:11500/v1", api_key="unused")

The first request from the app raises a consent prompt. To check the gateway from a terminal without involving an app's settings:

curl.exe http://127.0.0.1:11500/locai/health
curl.exe http://127.0.0.1:11500/v1/models

The first command answers straight away with the gateway's status. The second lists your models and, because curl.exe is an app like any other, raises a consent prompt the first time.

Common questions

Do I need an account or an internet connection?

No. There is no account, and the gateway makes no internet connections. It works with the network cable unplugged, as long as your runtime does.

Which runtimes does it work with?

It looks for Ollama, LM Studio, Jan, GPT4All, llama.cpp and Foundry Local on their usual ports and lists the ones that are running. On the Models tab you can add any other OpenAI-compatible server by its local address, for example http://127.0.0.1:1234. Addresses on other computers are not accepted.

What do Allow once, Always allow and Block do?

Allow once lets the running copy of the app through until it exits. Next time it starts, you are asked again. Always allow and Block save a rule for the app, which you can change or delete on the Apps tab.

If you do not answer in time (30 seconds unless you change it in Settings), the request fails with consent_timeout. The same app is not asked again for one minute, so wait a minute before you retry.

How do I change a decision I made?

Open the Apps tab, pick the app and change its rule, or delete the rule to be asked again.

Does it store my prompts?

Not unless you turn that on. By default the activity log keeps who called, when, which model, the result and token counts. On the Privacy tab you can choose to store a hash of each prompt, or the full prompt and response, which are then encrypted with Windows data protection. The privacy policy has the details.

What does redaction do?

Before a prompt is forwarded, the gateway scans it. Out of the box, credit card numbers and API keys are replaced with a placeholder, and a prompt that contains a private key is rejected. On the Privacy tab you can turn on more detectors (email addresses, phone numbers, IBANs, US social security numbers, Australian tax file numbers, JSON web tokens), choose whether each one masks, blocks or only counts, and add your own patterns. You can also have responses scanned.

What does Pause do?

While the gateway is paused, every request through it is refused with gateway_paused. Nothing is forwarded until you resume. Pause and resume are in the tray panel.

What is port takeover, and should I turn it on?

Some apps have Ollama's address, localhost:11434, built in and cannot be pointed anywhere else. With port takeover on, the gateway moves Ollama to port 11435 and answers on 11434 itself, so those apps go through the gateway without any change.

It is off by default. Turning it on restarts Ollama, and the app asks you first. Turn it on only if you have an app you cannot reconfigure. Turning it off puts Ollama back. If something goes wrong, see Undo port takeover by hand.

What happens to my apps when the gateway is not running?

Apps that point at the gateway's address cannot connect until it is running again. Your runtimes are not affected and still answer on their own addresses. The gateway starts when you sign in to Windows unless you turned that off in Settings.

What are per-app API keys for?

A script run by python.exe looks much like any other script run by python.exe. If you want one script to have its own rule and limits, create a key for that rule on the Apps tab and have the script send it as its API key. Keys start with lgw_. A key is shown once, when you create it. The app keeps only a hash of it.

Where is my data, and how do I delete it?

Everything is on your PC, in the app's own data folder. Activity older than the retention period (30 days by default, set on the Privacy tab) is deleted automatically. Uninstalling the app removes all of its data. The privacy policy lists what is kept and for how long.

Troubleshooting

My app cannot connect to 127.0.0.1:11500

  • Check that Locai Gateway is running: look for its icon in the notification area of the taskbar, or start it from the Start menu.
  • Another program may be using port 11500. The gateway keeps retrying and records the problem. Choose a different port in Settings, then use the new port in your apps.
  • Use 127.0.0.1, localhost or [::1] as the host. The gateway does not accept requests addressed to your PC's network name or network address.

I did not see a consent prompt

  • Prompts arrive as Windows notifications. Check that notifications are turned on for Locai Gateway in Windows Settings, under System, then Notifications, and that Do not disturb is off.
  • If a prompt timed out, the same app is not asked again for one minute. Wait, then try again.
  • If the app already has a rule, there is no prompt: the rule decides. Look for the app on the Apps tab.

A runtime is missing from the Models tab

  • Make sure the runtime is running and its local server is switched on. Some runtimes, such as LM Studio and Jan, only start their server when you ask them to.
  • If the runtime uses a port other than its usual one, add it on the Models tab with its local address.

An app still reaches Ollama without asking

The app is talking to Ollama's own port, not to the gateway. Change the app's address to the gateway's, or turn on port takeover. The gateway reports apps it sees connecting to a runtime directly.

Model downloads or deletes through the gateway are refused

Ollama's model management requests (pull, push, create, copy, delete) are blocked by default and fail with endpoint_not_allowed. To allow them, allow model management in Settings and include management requests in the rule of the app that should be able to make them.

Error codes

When the gateway refuses a request, the app receives an error with one of these codes. Requests to the OpenAI API paths get the code in the error.code field. Requests to the Ollama API paths get the message only.

CodeStatusMeaning and what to do
consent_timeout403The consent prompt was not answered in time. Wait a minute, try again and answer the prompt.
consent_denied403You chose Block for this app. Change its rule on the Apps tab.
app_denied403A rule or setting blocks this app. Check the Apps tab and the unknown-apps setting.
model_not_allowed403The app's rule does not include this model.
endpoint_not_allowed403The app's rule does not include this kind of request, or model management is turned off.
invalid_host403The request was not addressed to 127.0.0.1, localhost or [::1].
key_required401This app needs a Locai Gateway API key. Create one on the Apps tab and send it as a Bearer token.
key_invalid401The key is wrong, revoked, or belongs to a rule that no longer exists.
model_not_found404No running runtime has a model with that name. Check the Models tab.
unknown_endpoint404The gateway does not support that path.
redaction_blocked422The prompt contains something a detector is set to block, by default a private key. See the Privacy tab.
rate_limited429The app passed its requests-per-minute limit. The reply says when to retry.
budget_exhausted429The app used its daily or monthly token budget.
concurrency_limit429The app has too many requests running at once.
body_too_large413The request is larger than the gateway accepts.
bad_json400The request body is not valid JSON.
gateway_paused503The gateway is paused. Resume it from the tray panel.
upstream_unavailable503The runtime that has the model cannot be reached. Start it.
upstream_error502The runtime sent a reply the gateway could not use.

Undo port takeover by hand

The normal way is to turn port takeover off in Locai Gateway, on the Models tab. That puts Ollama's setting back and restarts Ollama. Use the steps below only if that is not possible, for example because the app was removed while port takeover was on and Ollama now answers on port 11435 instead of 11434.

Port takeover works by setting one environment variable for your Windows account, OLLAMA_HOST, to 127.0.0.1:11435. Ollama reads it when it starts. To undo it:

  1. Open the Start menu, type environment variables and choose Edit environment variables for your account.
  2. Under User variables, select OLLAMA_HOST.
  3. If you never set this variable yourself, choose Delete. If you had your own value before, choose Edit and put your value back.
  4. Choose OK to close the window.
  5. Restart Ollama: right-click its icon in the notification area and choose Quit, then start it again from the Start menu.

The same thing in PowerShell, for the case where you had no value of your own:

[Environment]::SetEnvironmentVariable("OLLAMA_HOST", $null, "User")

Then restart Ollama and check that it is back on its usual port:

curl.exe http://127.0.0.1:11434/api/version

Uninstall

  1. If port takeover is on, turn it off first, so that Ollama goes back to its usual port.
  2. Point your apps back at their runtimes' own addresses.
  3. In Windows Settings, open Apps, then Installed apps, find Locai Gateway and choose Uninstall.

Uninstalling removes the app's data: the activity log, your rules and settings, keys and logs.
